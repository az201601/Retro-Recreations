## 2. 验证清单（按优先级）

### V1 — CHR 银行号真实序列（解 0–14 之谜，最高优）

- 断点：`$C298`（CHR 切换，X=CHR0，Y=CHR1）、`$C2C5`（PRG 切换，A=银行）
- 记录：每帧的 `$1D/$1E/$1F/$20`（CHR 银行）、`$40`（状态）、`$0600`（OAM 状态）
- 预期：确认 `$DAC7` 表的 16/19/21/23/24/25（背景）与 12/14/25（精灵）是否真实生效
- 若精灵银行 14 真实生效 → 查 PPU 图案表查看器中 `$1000` 的实际图块（与 `chr4k_14.png` 对比）
  - 若查看器显示清晰精灵 → 我们的 PNG 渲染格式错（平面顺序/8×16），修正提取器
  - 若查看器也显示噪声 → 精灵数据在 PRG（`$053B` 队列），追 V2

### V2 — CHR 上传队列数据源（`$053A/$053B`）

- 断点：`$C34F`（队列处理）、`$D691`（`($00),Y`→`$05AE` 拷贝）
- 记录：队列条目 `[hi,lo,count,data…]` 的 PPUADDR 与数据来源 PRG 银行/地址
- 目的：确认精灵图形是否经 PRG 上传到 CHR RAM（若是，CHR ROM 12/14 为填充）

### V3 — 状态触发（`$40` 0–9）

- 断点：`$D63D`（状态加载，A=`$40`）、`$C54E`（分发）
- 记录：标题→游戏→过关→结算的 `$40` 序列 + 触发按键/事件
- 目的：确认 10 状态的真实含义（标题/演示/游戏/结算…），修正 `scr_game_state`

### V4 — 实体字段（`$0700` 数组）

- 观察：`$0700–$07FF` 每帧变化（玩家 X=3 时）
- 记录：`$079C`（位置）、`$07AE/$07B4`（速度累加）、`$07A2`（动画）、`$07BA/$07C0`（速度）
- 目的：确认 `docs/04` §2 字段表，校准 GMS `obj_player` 数值（移速/跳速/重力）

### V5 — 音乐序列（`$F8–$FB` + `$4000` 写）

- 断点：`$8200`（调度，A=轨号）、`$812D/$8154`（脉冲输出）
- 记录：轨号序列 + `$4002/$4003` 周期值（音高）
- 目的：为阶段 C 音乐解码提供对照（银行 5 指针表）

### V6 — 关卡数据（银行 0–2）

- 断点：`$D903`（CHR 银行表加载）、`$D7AD`（区域索引 `$71`）
- 记录：每关的 `$DAC7` 指针 + 银行 2 表内容 + nametable 写入（`$2006/$2007`）
- 目的：解码第一关图块地图（阶段 C 垂直切片）

## 6. 自定义模拟器验证结果（2026-11-13，`tools/nes_emu.py`）

沙箱无 GUI 模拟器，编写最小 NES 模拟器（6502 + MMC1 + PPU/APU stub + 控制器）进行动态验证。

### 6.1 模拟器实现

- **CPU**：6502 官方 opcode 全表（`OPS` 字典），NMI/IRQ/RESET/BRK/RTI，分页 wrap bug（`JMP ($xxFF)`）
- **MMC1**：串行 5-bit 移位，`$8000–$9FFF` 控制 / `$A000–$BFFF` CHR0 / `$C000–$DFFF` CHR1 / `$E000–$FFFF` PRG；复位（bit7=1）强制 16KB 固定末银行（`control=$0C`）
- **PPU stub**：寄存器 `$2000/$2001/$2003/$2005/$2006/$2007`，VRAM nametable 2KB（垂直镜像），palette 32B，OAM 256B，VBlank（`$2002` bit7）+ NMI（`$2000` bit7），OAM DMA `$4014`（513 cycle stall）
- **APU stub**：`$4000–$4013` 写入忽略，`$4015/$4017` 返回 0
- **控制器**：`$4016/$4017` strobe/latch，脚本输入（Start 按键）
- **帧时序**：29780 cycles/帧，VBlank 置位 + NMI 触发

### 6.2 验证结果

| 验证项 | 结果 | 证据 |
|---|---|---|
| **V1 CHR 银行序列** | ✅ 部分验证 | 状态 0：CHR `31,31,31,31`（字体银行）；状态 1：CHR `31,29,31,29`（标题背景 29 + 字体 31）。`$DAC7` 表的 16/19/21/23/24/25 未在前 600 帧出现（需进入游戏状态 2+） |
| **V2 CHR 上传队列** | ⏳ 未验证 | `$053A/$053B` 在状态 1 保持 `00/00`（无队列活动）；需进入游戏状态触发上传 |
| **V3 状态触发** | ✅ 已验证 | `$40` 0→1 在 frame 144（Start 按键后）；状态 0 header `$D719`（`02 81 B0 91 B0 40...`），状态 1 header `$D738`（`22 81 B0 91 B0 00...`）。`$05AE` 从 `00...` 变为 `0F 0F 0F 20...`（银行 3 数据） |
| **V4 实体字段** | ✅ 初步验证 | `$0700` 在状态 1：`00 10 20 30`（实体 0 字段），`80 80 80 80`（实体 6/2 掩码），`92 92 92 92`（实体 8？），`08 08 08 08`（实体 12？），`B5 92`（实体 14？）。需进入游戏状态观察玩家移动 |

### 7.4 PPU 查看器对比（2026-11-13，用户截图 `analysis/fceux_ppu_stage1_start.png`）

用户在第一关开始（状态 4，CHR 15/0）截 PPU 查看器：

- **左表 `$0000`（银行 15）**：清晰的关卡图形（绿/红图块、顶部 "GAL" 文字、右下 Chip 精灵）—— 与 `analysis/chr/chr4k_15.png` **结构完全一致**（FCEUX 彩色版 vs 我们的灰度版）✅
- **右表 `$1000`（银行 0）**：红/绿/黑斑点噪声 —— 与 `analysis/chr/chr4k_00.png` **噪声结构一致** ✅

**结论：我们的 PNG 提取器是正确的**（两张图都与 FCEUX 吻合），"噪声"是真实数据，不是渲染 bug。

**状态 4 的精灵来源**：Chip 精灵出现在**左表（银行 15，`$0000`）**，说明状态 4 时背景和精灵**共用 `$0000`**（`$2000` 的精灵图案表选择位=0），右表银行 0 未被使用（噪声无所谓）。

### 7.5 状态 3 PPU 对比（2026-11-13，用户截图 `analysis/fceux_ppu_state3.png`）

用户在状态 3 截 PPU 查看器：

- **左表 `$0000`（银行 24）**：蓝/绿背景图块 —— 与 `analysis/chr/chr4k_24.png` **结构一致** ✅
- **右表 `$1000`（银行 25）**：Chip 大头像（绿/蓝/紫，含双手）—— 与 `analysis/chr/chr4k_25.png` **完全一致** ✅

**结论：此截图为 CHR 24/25（状态 3 早期，帧 1247），不是 24/14。** 银行 24/25 提取正确，银行 25 = Chip 剧情/标题大头像。

### 7.6 状态 3（31/14）PPU 对比（2026-11-13，用户截图 `analysis/fceux_ppu_state3_31_14.png`）

用户在状态 3（CHR 31/14）截 PPU 查看器：

- **左表 `$0000`（银行 31）**：字体（0-9、A-Z、a-z，蓝/黄）—— 与 `analysis/chr/chr4k_31.png` **完全一致** ✅
- **右表 `$1000`（银行 14）**：蓝/黄/白斑点噪声 —— 与 `analysis/chr/chr4k_14.png` **噪声结构一致** ✅

**结论：银行 14 在 FCEUX 里也是噪声，我们的提取器正确。** "噪声"是真实数据。

**CHR 0–14 之谜（已解）**：银行 0–14 的噪声数据真实存在，但游戏显示时**未使用 `$1000`**（精灵共用 `$0000`）：
- 状态 4（第一关开始，15/0）：Chip 在左表银行 15（`$0000`），右表银行 0 未用
- 状态 3（31/14）：左表银行 31 为字体，右表银行 14 噪声未用（状态 3 为过场/剧情，无需精灵）

- 银行 15 是第一关主图形银行（含背景+Chip 精灵），银行 0–14 为填充/未用

**下一步**：查 `$2000` 控制位确认精灵图案表选择（FCEUX 断点 `$2000` 写），或直接用银行 15 做第一关原型。
