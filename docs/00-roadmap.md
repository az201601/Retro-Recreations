# 00 — 宏伟计划路线图

> 目标：在 **GMS 1.4.1760** 里重制童年经典。第一站《松鼠大战2》，后续按同一流水线推进其他游戏。
> 本文档是总纲：阶段、里程碑、每阶段交付物、风险与决策点。

## 1. 总体策略

**不做逐指令 CPU 模拟器**（在 GML 里跑 6502 解释器太慢且无意义），而是做**行为级重制**：

1. 静态反汇编 + 动态验证，摸清原版的**系统行为**（PPU/APU/输入/状态机/实体/音乐）
2. 把 NES 系统抽象成 GMS 里的**等价层**（`nes_ppu` / `nes_apu` / `nes_input` / `nes_mmc1` 兼容层）
3. 游戏逻辑按原版**状态机 + 实体脚本**重写为 GML，但保持原版的数值、时序、关卡布局
4. 美术：先用 CHR 提取的图块做**占位**，再决定重绘 / 授权 / 保留（见 `08` 版权）
5. 音乐：先解码 APU 序列数据，再转成 GMS 可播放的音频 / 序列器

这样既能 1:1 还原手感，又能在 GMS 里长期维护。

## 2. 阶段划分

### 阶段 A — 全方位反汇编（当前，M0）

| 任务 | 交付物 | 状态 |
|---|---|---|
| ROM 取证（头、校验、银行、熵） | `docs/01` + `analysis/rom_forensics.md` | ✅ |
| 6502 反汇编器（递归 + 线性） | `tools/dis6502.py` + `disassembly/*.asm` | ✅ |
| 复位 / NMI / MMC1 / PPU / 手柄追踪 | `docs/03` | ✅ |
| 状态机（10 状态 + 20B 头） | `docs/03` §5 | ✅ |
| 实体系统 + 音乐调度初步解析 | `docs/04` | ✅（初步） |
| 数据银行结构 | `docs/05` | ✅（初步） |
| CHR 图形提取 | `docs/06` + `analysis/chr/*.png` | ✅（15–31）/ ⚠️（0–14） |
| GMS 工程骨架 | `gms/ChipNDale2_GMS14/` | ✅ |

### 阶段 B — 动态验证（M1）

- 用模拟器（Mesen/BizHawk）设断点验证静态推断：
  - `$1D–$20` CHR 银行号的真实取值序列（每帧记录）
  - `$0600` OAM 缓冲、`$0700` 实体数组的字段含义
  - `$053A` CHR 上传队列的条目格式
  - 10 个状态的实际触发条件（标题→演示→游戏→结算…）
- 录制原版关键画面（标题、第一关、Boss）作为 GMS 对照基准
- 交付：`docs/09-dynamic-validation.md`（待建）+ 截图/录像对照表

### 阶段 C — 数据解码（M2）

- 关卡数据：银行 0–2 图块地图格式（`$B081` 等调色板表已解，图块地图待解）
- 实体脚本：`$92B6` 指针表 + `($F5),Y` 流的操作码表（`$FE` 终止、`$E0` 调色板、`$40/$80/$A0` 等）
- 音乐数据：银行 5 指针表（`$8014/$809C/…`）+ `$F8–$FB` 序列器
- 文本：字体银行 31 的图块索引 → 字符映射（标题、对话、结算）
- 交付：`docs/10-level-data.md`、`docs/11-music-data.md`（待建）+ 解码脚本 `tools/decode_*.py`

### 阶段 D — GMS 可玩原型（M3）

- 标题画面（状态 0/9）+ 第一关可走、可跳、可扔橡子
- 敌人巡逻 + 碰撞 + 生命/分数 HUD
- 音乐/音效占位（GMS `sound_play`）
- 交付：可运行的 `.gmx` + `docs/07` 映射手册的实测修订

### 阶段 E — 全关卡 + Boss + 完整流程（M4）

- 9 关（原版关卡数待动态验证确认）+ Boss 战 + 结局
- 完整状态机：标题→选关→游戏→过关→结算→结局
- 交付：完整可通关版本

### 阶段 F — 抛光与发布（M5）

- 16:9 / 全屏 / 手柄支持（GMS 1.4 手柄有限，需键盘映射 + 可选 XInput 扩展）
- 存档（GMS `ini` / `ds_map` 序列化）
- 版权合规审查（素材重绘清单）

## 3. 关键决策点（已拍板 2026-11-13）

| 决策 | 选择 | 影响 |
|---|---|---|
| **还原度** | ✅ **1:1 像素级（256×240，60Hz）** | 房间 256×240、视图 256×224、整数缩放 ×3 |
| **美术来源** | ✅ **个人保留原版**（CHR 提取占位，本地使用） | 原型直接用提取图块；发布前仍需重绘（见 `docs/08`） |
| **音乐来源** | APU 解码转音频（待阶段 C） | 先占位，后解码银行 5 |
| **输入** | 键盘（方向+Z/X/Enter） | GMS 1.4 手柄 API 有限，手柄为辅 |
| **下一步** | ✅ **动态验证（阶段 B）** | 见 `docs/09-dynamic-validation.md` + `tools/*_chr_log.lua` |
| **后续游戏** | 《松鼠大战1》→《快打旋风》→…（按你小时候清单） | 仓库是否按游戏分子目录 |

## 4. 风险

- **CHR 0–14 之谜**：精灵银行呈噪声，若为加密/压缩，需额外解码（见 `docs/06` §5）。缓解：先用银行 25 的 Chip 精灵 + 银行 15–31 背景做原型。
- **GMS 1.4.1760 旧版限制**：无 Tilemap、无物理引擎、声音格式有限。缓解：`docs/07` 已给替代方案（背景图 + 手动碰撞 + ogg/wav）。
- **版权**：Disney/Capcom 素材不可分发。缓解：`docs/08` 合规清单，原型仅本地验证。
- **工期**：全关卡是最大头。缓解：先打通“标题→第一关→过关”垂直切片。

## 5. 下一步（建议顺序）

1. 你确认 §3 决策（或先选默认 A/A/A）
2. 动态验证（阶段 B）：在模拟器里抓 CHR 银行号 + 状态触发
3. 解码第一关数据（阶段 C 垂直切片）
4. GMS 原型（阶段 D）
