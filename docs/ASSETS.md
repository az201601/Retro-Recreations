# Asset naming contract

Everything in `assets_vec/` is generated by the scripts in `tools/`; nothing is
hand drawn, resized or recoloured.  This document is the contract between the
extractor and the GML code pack (`code/`).

## Path → sprite name

```
assets_vec/sprites/<character>/<anim>.png      ->  spr_<character>_<anim>
assets_vec/sprites/<character>/<anim>_fNN.png  ->  (single frame, do not import)
assets_vec/ui/<name>.png                       ->  spr_<name>  (also spr_ui_<name>)
assets_vec/backgrounds/<level>/screen_00.png   ->  background  bg_<level>
assets_vec/backgrounds/<level>/tileset.png     ->  tileset     ts_<level> (optional)
```

The GML resolves names with `asset_get_index()`, so a sprite that has not been
imported yet disables its clip instead of crashing the game.
`tools/check_assets.py` compares the names used in `code/` against the files in
`assets_vec/` and exits non-zero on a real mismatch
(missing-but-known names are listed in `code/assets_optional.txt`).

## Sprite metadata

`assets_vec/sprites/sprites.json` is a list of entries:

```json
{ "character": "chip", "anim": "walk",
  "image": "sprites/chip/walk.png",
  "frame_w": 20, "frame_h": 25, "count": 4,
  "origin": [10, 25],
  "sources": [ {"trace": "pi_holdR", "frame": 5601}, ... ] }
```

* `image` is a horizontal strip: frame `i` starts at `x = i * frame_w`.
* `origin` is in single-frame coordinates; all in-level sprites are
  **centre-bottom**, so a sprite's `y` is its ground contact point.
* `count` is the number of frames in the strip.
* `sources` records exactly which emulator trace / frame each frame came from,
  so every pixel is reproducible.

Cut-scene artwork keeps its own natural size (e.g. the 234×32 `logo/pair.png`),
which is why `frame_w` must always be read from the JSON instead of assumed.

## Level data

`assets_vec/backgrounds/level01/`

| file | meaning |
|---|---|
| `screen_00.png` | 256×240 screen, exact NES output with all sprites removed |
| `canvas.png` | 512×480 full scroll canvas (4 name tables) |
| `tileset.png` | 16×16 metatiles, 16 per row, transparent where empty |
| `tileset_8x8.png` | raw 8×8 tiles in the order given by `tiles_8x8` |
| `info.json` | palette, CHR windows, scroll, `map[15][16]` metatile indices |
| `collision.json` | standable rectangles derived from the pixel art |

`screen_00.png` is reconstructed from VRAM (name tables + attributes + palette +
CHR bank), not screenshotted, which is why it contains no sprites at all and
matches the real frame pixel for pixel everywhere the background is visible.

## Colour

The exported PNGs already carry the final NES colours; `palettes/palettes.json`
and the `palette` / `palette_rgb` fields in `info.json` exist for runtime
tinting and for re-rendering tiles at other times of day. The NES palette is
also mirrored in `global.NES_PAL` (`code/scripts/scr_config_init.gml`).
